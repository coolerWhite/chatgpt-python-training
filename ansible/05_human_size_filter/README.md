# Задание 5. Свой фильтр Ansible: удобный размер файла

Напиши собственный Jinja-фильтр `training_human_size` для Ansible. Фильтр
получает целое количество байт и возвращает короткую человекочитаемую строку:
например, `1536` превращается в `1.5 KiB`.

В прошлом задании модуль возвращал размер файла в байтах. Теперь сделаем
инструмент, которым такой результат можно удобно отображать в playbook.

**Темы:** filter plugins, Jinja-фильтры, классы как оболочка Ansible, циклы,
проверка аргументов, форматирование чисел.

**Ориентир по времени:** 35–50 минут.

## Что сделать

Создай файл `filter_plugins/training_filters.py`. В нём должны быть функция
`human_size(value)` и класс `FilterModule`.

Фильтр должен:

1. Принимать неотрицательное целое число байт.
2. Использовать единицы `B`, `KiB`, `MiB` и `GiB`.
3. Делить значение на 1024, пока оно не станет меньше 1024 или пока не будет
   достигнута последняя единица.
4. Для байтов возвращать целое число без десятичной части: `512 B`.
5. Для остальных единиц оставлять один знак после точки: `1.5 KiB`.
6. Для отрицательного числа или значения неверного типа выбрасывать
   `AnsibleFilterError` с понятным сообщением.
7. Зарегистрировать функцию под именем фильтра `training_human_size`.

Готовое решение в задании не приводится. Файл `playbook.yml` уже содержит
примеры и автоматические проверки результата.

## Где выполняется фильтр

Модуль из прошлого задания выполнялся на целевом хосте. Jinja-фильтр работает
на управляющей машине, где запускается `ansible-playbook`: Ansible использует
его во время обработки выражений `{{ ... }}`.

Ansible автоматически ищет локальные фильтры в директории `filter_plugins`
рядом с playbook:

```text
05_human_size_filter/
├── README.md
├── playbook.yml
└── filter_plugins/
    └── training_filters.py
```

## Функция преобразования

Начни с обычной Python-функции:

```python
def human_size(value):
    ...
```

Удобно хранить единицы в кортеже:

```python
units = ("B", "KiB", "MiB", "GiB")
```

Понадобятся две переменные:

- текущее числовое значение размера;
- индекс текущей единицы в `units`.

Пока размер не меньше 1024 и доступна следующая единица, дели значение на
1024 и увеличивай индекс. Ограничение по индексу важно: для очень большого
числа цикл должен остановиться на `GiB`, а не выйти за границы кортежа.

Для форматирования пригодятся f-строки:

```python
f"{number:.1f} {unit}"
```

Запись `.1f` означает один знак после точки.

## Проверка входного значения

Импортируй исключение Ansible:

```python
from ansible.errors import AnsibleFilterError
```

Проверь тип через `isinstance(value, int)` и отдельно исключи `bool`.
В Python значения `True` и `False` технически являются подклассами `int`,
но считать их размером файла в этом задании не нужно.

После проверки типа отдельно проверь, что число не отрицательное. При ошибке
используй `raise AnsibleFilterError("понятное сообщение")`.

## Как Ansible находит функцию

Одной функции недостаточно: плагину нужна стандартная оболочка Ansible.
Создай класс `FilterModule` с методом `filters(self)`. Метод должен вернуть
словарь, где:

- ключ — имя фильтра в playbook: `training_human_size`;
- значение — сама функция `human_size`, без круглых скобок.

Псевдокод:

```text
класс FilterModule:
    метод filters:
        вернуть отображение:
            имя фильтра → функция human_size
```

Скобки важны: `human_size` означает «передать функцию», а `human_size()` —
«вызвать функцию прямо сейчас».

## Как фильтр используется в playbook

В Jinja значение слева от `|` передаётся функции как первый аргумент:

```yaml
msg: "{{ 1536 | training_human_size }}"
```

Это соответствует обычному Python-вызову `human_size(1536)`.

В подготовленном playbook задача `debug` покажет преобразования, а `assert`
сравнит их с ожидаемыми строками. Если хотя бы один результат отличается,
playbook завершится ошибкой и покажет проблемный пример.

## Запуск

Выполняй из корня репозитория:

```bash
ansible-playbook -i localhost, ansible/05_human_size_filter/playbook.yml
```

Если используешь окружение репозитория:

```bash
.venv/bin/ansible-playbook -i localhost, ansible/05_human_size_filter/playbook.yml
```

## Ожидаемые результаты

| Вход | Результат |
| ---: | --- |
| `0` | `0 B` |
| `999` | `999 B` |
| `1024` | `1.0 KiB` |
| `1536` | `1.5 KiB` |
| `1048576` | `1.0 MiB` |
| `1073741824` | `1.0 GiB` |

## Самопроверка

Перед запуском через Ansible можно временно вызвать функцию обычным Python-кодом
и проверить несколько значений. Затем запусти playbook и убедись, что задача
`Проверить результаты фильтра` завершилась со статусом `ok`.

Дополнительно проверь вручную:

- отрицательное число;
- строку вместо числа;
- `True` или `False`;
- очень большое число, которое должно остаться в `GiB`.

Когда всё заработает, сообщи — проверим реализацию, ошибки и читаемость кода.
