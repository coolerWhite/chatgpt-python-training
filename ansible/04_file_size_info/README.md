# Задание 4. Первый модуль Ansible: размер файла

Напиши свой модуль `training_file_info` на Python. Он получает путь к файлу
и возвращает его размер в байтах. Запускай его через Ansible на `localhost`.

Ты уже работал с функциями, словарями, `Path` и исключениями. Здесь добавится
оболочка Ansible: приём параметров и передача результата в playbook.

**Темы:** `AnsibleModule`, `argument_spec`, `exit_json`, `fail_json`, `pathlib`.
**Ориентир по времени:** 45–60 минут после установки Ansible.

## Что сделать

Создай в этой директории файл `library/training_file_info.py`.
Готового решения здесь нет; `playbook.yml` и `sample.txt` уже подготовлены
для запуска и самопроверки.

Модуль должен:

1. Принимать обязательный строковый параметр `path`.
2. Проверять, что путь указывает на обычный файл.
3. Возвращать `changed: false`, `path` (переданную строку) и `size_bytes`
   (целое число — размер в байтах).
4. Для отсутствующего файла, директории или ошибки доступа завершаться
   через `fail_json` с понятным `msg`. Точный текст сообщения любой.
5. Работать с `--check` и возвращать те же данные: он только собирает информацию.

Файлы создавать, изменять и удалять модуль не должен. Символические ссылки,
гонки при изменении файла и специальные файлы отдельно разбирать не нужно.
Коллекция, публикация в Galaxy и автоматические тесты пока не требуются.
В реальной работе для такой проверки есть `ansible.builtin.stat`;
свой модуль здесь нужен для обучения.

## Материал перед решением

### Где выполняется Python-код

Ansible запускает модуль на целевом хосте. Поэтому `path` относится к файлу
на этом хосте. В нашем playbook целевой хост — твоя машина, используется
`connection: local`, SSH и отдельный сервер не нужны.

Ansible находит локальный модуль в директории `library` рядом с playbook.
Имя файла без `.py` становится именем модуля в YAML.

### Параметры и результат

Импортируй помощник:

```python
from ansible.module_utils.basic import AnsibleModule
```

Внутри функции `main()` создай объект `AnsibleModule`. Передай ему:

- `argument_spec={"path": {"type": "str", "required": True}}`;
- `supports_check_mode=True`.

После этого значение параметра доступно через `module.params["path"]`.
Ansible сам проверяет наличие обязательного параметра — ручной разбор
аргументов командной строки не нужен.

Объект — это значение, у которого есть свои данные и методы. Классы писать
в этом задании не придётся: ты используешь готовый объект `module`.

`module.exit_json(...)` передаёт успешный результат и завершает выполнение.
Именованные аргументы становятся полями результата. Например, для другого
модуля, возвращающего имя приложения:

```python
module.exit_json(changed=False, application="demo")
```

`module.fail_json(msg="Понятное описание ошибки")` сообщает Ansible об ошибке
и тоже завершает выполнение. `print()` для результатов и отладки здесь
не используй: Ansible ожидает служебный JSON, который готовят эти методы.

`changed` означает, изменил ли модуль состояние хоста. Получение размера
ничего не меняет, поэтому значение всегда `False`, даже если размер файла
отличается от результата предыдущего запуска.

В режиме `--check` Ansible обычно прогнозирует изменения. Наш модуль только
читает информацию, поэтому отдельная ветка с ранним выходом ему не нужна.

### Размер файла через `Path`

```python
from pathlib import Path

item = Path("example.txt")
```

- `item.is_file()` проверяет, указывает ли путь на обычный файл.
- `item.stat().st_size` возвращает размер в байтах.
- Ошибки файловой системы можно перехватить через `except OSError as error`.
  Текст ошибки доступен через `str(error)`.

Не читай содержимое целиком для вычисления размера. Размер текста в символах
может отличаться от размера файла в байтах, например для русских букв в UTF-8.

### Отдели работу с файлом от Ansible

Напиши функцию `inspect_file(path)`, которая возвращает словарь с полями
`path` и `size_bytes`. Если путь не указывает на файл, вызови
`raise ValueError("...")`. Ошибки `OSError` пусть передаются вызывающему коду.

`raise` создаёт исключение, которое можно поймать через `try/except`.
В `main()` вызывай эту функцию и перехватывай `ValueError` и `OSError`,
переводя их в `module.fail_json(...)`. Успешный результат передай через
`module.exit_json(...)` вместе с `changed=False`.

Функция `inspect_file` не должна печатать результат или вызывать методы
Ansible. Так файловую логику можно проверить отдельно.

В конце файла добавь вызов точки входа:

```python
if __name__ == "__main__":
    main()
```

При запуске файла Python вызовет `main()`. При импорте файла для проверки
отдельной функции этот блок не выполнится.

## Подготовка и запуск

Команды ниже выполняй из корня репозитория. Если Ansible уже установлен
в подходящем окружении, используй его. Иначе установи `ansible-core`
в отдельное окружение вне репозитория:

```bash
python3 -m venv /tmp/python-training-ansible-venv
source /tmp/python-training-ansible-venv/bin/activate
python -m pip install ansible-core
```

После создания модуля запускай:

```bash
ansible-playbook -i localhost, ansible/04_file_size_info/playbook.yml
ansible-playbook -i localhost, ansible/04_file_size_info/playbook.yml --check
```

Запятая в `localhost,` нужна: это список хостов в командной строке.
В playbook указан текущий Python-интерпретатор Ansible, поэтому локальному
модулю не нужно отдельное окружение на целевом хосте.

`register: file_result` сохраняет ответ модуля. Следующая задача `debug`
показывает его. В результате для `sample.txt` должны быть такие поля
(путь будет абсолютным, Ansible может добавить служебные поля):

```yaml
changed: false
path: /путь/к/репозиторию/ansible/04_file_size_info/sample.txt
size_bytes: 6
```

## Самопроверка

Другой путь можно передать без редактирования playbook:

```bash
ansible-playbook -i localhost, ansible/04_file_size_info/playbook.yml \
  -e '{"target_path": "/путь/к/другому/файлу"}'
```

| Случай | Ожидаемое поведение |
| --- | --- |
| Исходный `sample.txt` | `size_bytes: 6`, `changed: false` |
| Повторный запуск | Тот же результат, без изменений |
| Запуск с `--check` | Те же поля и размер, задача не пропущена |
| Пустой файл | `size_bytes: 0`, `changed: false` |
| Несуществующий путь | Задача завершается с `FAILED` и понятным `msg` |
| Путь к директории | Задача завершается с `FAILED` и понятным `msg` |

Временный пустой файл создай командой `touch /tmp/training-empty.txt` и передай
его путь через `target_path`. Отсутствующий путь выбери заведомо несуществующий.
Для проверки директории передай абсолютный путь к директории этого задания.
Не нужно специально менять права доступа: достаточно предусмотреть `OSError`.

Сначала проверь файловую функцию, затем подключи Ansible. Когда всё заработает,
сообщи, что задание готово — проверим решение по этим требованиям.
